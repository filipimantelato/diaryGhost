# Benchmark — Fase 1 (2026-11-06)

**Build:** Release, self-contained, ReadyToRun, win-x64 (`scripts/publish.ps1`)
**Máquina:** AMD Ryzen 5 5600X (12 threads lógicas), 32 GB RAM, Windows 11 (build 26300)
**Método:** `scripts/measure.ps1` — pasta de dados isolada, 8 s de aquecimento, 30 s de amostra por modo, encerramento com `--quit`.

| Modo | CPU no período | Memória privada | Working set | Threads |
|---|---|---|---|---|
| Somente bandeja (`--minimized --no-widget`) | 0 ms / 30 s | 50,0 MB | 104,3 MB | 17 |
| Widget visível (`--minimized`) | 0 ms / 30 s | 70,7 MB | 135,5 MB | 17 |
| Janela principal + widget (`--show-main`) | 0 ms / 30 s | 70,6 MB | 130,0 MB | 18 |

Inicialização (do início do processo até o shell pronto): 5 240 ms na primeira execução após publicar
(cache de disco frio), 787 ms e 840 ms nas seguintes.

## Leitura
- O consumo de CPU ocioso é zero em todos os modos: nenhum timer de alta frequência; o relógio do
  widget acorda uma vez por minuto e apenas quando visível.
- O *working set* inclui páginas compartilhadas de DLLs do sistema; **memória privada** é a métrica
  que representa o custo real do app.
- O piso de ~50 MB é o runtime .NET + WPF carregados. A diferença bandeja → widget (~20 MB) é a
  primeira árvore visual e os recursos de tema.
- Abrir a janela principal na Fase 1 quase não acrescenta memória porque as páginas ainda são leves;
  isso deve ser remedido a cada fase.

## Orçamento proposto (revisar a cada fase)
| Modo | Privada | CPU ocioso |
|---|---|---|
| Somente bandeja | ≤ 70 MB | ≈ 0 |
| Widget visível | ≤ 100 MB | ≈ 0 (picos só em animação ou evento) |
| Janela principal | ≤ 180 MB | ≈ 0 parado |
