# Benchmark — Fase 2 (2026-11-06)

**Build:** Release, self-contained, ReadyToRun, win-x64 · **Máquina:** Ryzen 5 5600X (12 threads), 32 GB, Windows 11
**Condição:** Spotify **tocando** durante todas as medições (pior caso para o widget). Amostras de 30 s.

## Resultado final (padrões de fábrica) — `scripts/measure-media.ps1`

| Estado | CPU no período | CPU média | Memória privada |
|---|---|---|---|
| Compacto (indicador estático, padrão) | 78 ms | 0,02% | 67 MB |

Observação: este script usa UI Automation para trocar os estados, e um cliente UIA conectado faz o WPF
emitir eventos de acessibilidade entre processos — os números acima incluem esse custo.

## Medições sem UI Automation (estado gravado no banco antes de abrir)

| Estado | CPU / 30 s |
|---|---|
| Expandido — Início | 78 ms |

| Compacto — **equalizador animado (15 fps)** | **656 ms** |

## Decisões tomadas com base nos números
1. **Equalizador animado desligado por padrão** (opção em Configurações → Widget). Animação contínua numa
   janela em camadas custa ~14× o estado parado.
2. **Progresso a 1 Hz só com o ponteiro sobre a ilha**, a cada 5 s fora dele. A posição é extrapolada do
   timestamp informado pelo app, então não há deriva.
3. Pincel da capa e lista de chips só são recriados quando mudam.

## Em aberto
- O painel Mídia expandido ainda custa ~4× o Início parado. Hipóteses testadas e descartadas: recriação
  de chips/capa e interpolação da capa. A causa exata exige um profiler (PerfView/ETW) — próximo passo.
- O pacote publicado passou de 159 MB para 213 MB: projeção WinRT do Windows SDK, necessária para
  `Windows.Media.Control`.

## Comparação com a Fase 1
Memória privada só bandeja: 50 → 58 MB (serviços de mídia e Core Audio ativos). Widget: 71 → 67–111 MB
conforme o painel (capas decodificadas a 128 px, cache de 6 imagens).
